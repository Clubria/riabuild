# The launchers in `~/.riabuild/bin`, in Rust

**Status:** implemented
**Date:** 2026-08-28
**Code:** `riabuild-cli/crates/tasks/src/shims/launch.rs`, the three `handoff` functions
beside it in `shims/claude/launcher.rs`, `shims/codex.rs` and `shims/grok.rs`, and
`riabuild internal launch` / `riabuild internal ngrok` in `crates/cli/src/internal.rs`

## The problem

riabuild puts around thirty files into the developer's `PATH`, and most of them are one
`exec` line. Four were not.

`~/.riabuild/bin/claude` was ninety lines of `sh`. It cleared three environment variables,
claimed a Wayland display under three conditions, decided whether the harness binary it had
recorded was still there, rebuilt `PATH` through a `tr`/`grep`/`paste` pipeline when it was
not, matched `$PWD` against every checkout on the machine with a `case`, and then chose
between two `set --` lines under four more conditions. `codex` and `grok` were shorter
versions of the same thing, each with an argument scan on top. `ngrok` read a **credential**
out of a command substitution.

None of that is exotic shell. All of it is shell, and that is the problem:

- **There is no type checker.** A misspelled variable is the empty string. A branch that
  never runs is not an error.
- **There is no test that runs without a subprocess.** Half the assertions in those files'
  test modules were `script.contains("…")` — which proves a string is present, not that
  the program does anything. The other half wrote the script to a tempdir, made it
  executable, and ran it, which is a slow test that cannot cover the interactive branch at
  all: `cargo test` gives a child no terminal, so the `[ -t 0 ] && [ -t 1 ]` path was
  literally untestable and is annotated as such.
- **A mistake produces a different working program.** This is the sharp one. `grep -vxF`
  losing its `-x` still runs, and quietly takes every directory *under* the developer's
  home off their `PATH`. `${x:+--cwd "$x"}` still runs, and splits `/Users/Ada
  Smith/Clubria/…` back into two arguments. A `set --` branch that keeps
  `--exclude-dynamic-system-prompt-sections` on the agents-view line still runs, and turns
  `claude` into a listing of background agents that exits.

Every one of those is recorded, by name, in a comment in the file it would have broken. A
comment is a rule enforced by whoever reads it next.

## The decision

**Nothing riabuild writes into `$PATH` contains logic.** Every generated file in
`~/.riabuild/bin` is a shebang, some comments, and exactly one `exec` — of riabuild itself,
by absolute path, carrying what riabuild resolved when it wrote that file.

```sh
#!/bin/sh
# Generated by riabuild. Edits here are overwritten.
exec '/home/dev/.riabuild/riabuild/2026.08.28/riabuild' internal launch claude \
  --home '/home/dev/.riabuild/claude/<uuid>' \
  --binary '/home/dev/.riabuild/node/22.23.1/bin/claude' \
  --bin-dir '/home/dev/.riabuild/bin' \
  --settings '/home/dev/.riabuild/org-settings.json' \
  --checkout '/home/dev/Clubria/ai-builders-hub' \
  --default-checkout '/home/dev/Clubria/ai-builders-hub' -- "$@"
```

`shims::launch` is what that reaches. `Plan` is the flags; `World` is the machine, one
field per test the shell script used to run; `handoff(&Plan, &World) -> Handoff` is the
whole decision, pure, and is what every branch of every launcher is now unit-tested
through. `launch::run` gathers the `World`, calls `handoff`, and `exec`s.

| what the script did | what does it now |
|---|---|
| `case "$b" in /*) ;; *) b="" ;; esac` then `[ ! -x "$b" ]` | `launch::resolve_binary` |
| `printf '%s' "$PATH" \| tr ':' '\n' \| grep -vxF "$bin" \| paste -sd: -` | `launch::path_without` |
| `case "$PWD" in "$c"\|"$c"/*) …` | `claude::checkout_for` |
| `unset SSH_CONNECTION SSH_CLIENT SSH_TTY` | `RunOptions::env_remove` |
| `if [ $# -eq 0 ] && [ -t 0 ] && [ -t 1 ] && [ -z "$…" ]` | `claude::argument_line` |
| `for a do case "$a" in --yolo \| -a*) …` | `codex::names_an_approval_policy` |
| `NGROK_AUTHTOKEN=$(riabuild internal ngrok-token)` | `internal::ngrok` |

## What is kept rather than traded away

Three properties made the shell version tolerable, and losing any of them would make this a
worse design rather than a tidier one.

**The resolved values stay in the file.** `claude_accounts::check`, `codex_cli::check` and
`grok_cli::check` all compare a launcher on disk against what riabuild would write *now*,
which is how a Node upgrade, a riabuild upgrade and a hand edit are all detected as drift.
The tempting alternative — a launcher naming only its profile number, with everything else
resolved at launch time from `config.json` — would make all nine byte-identical and that
comparison worthless. It would also put reading riabuild's state on the path of every
`claude`, and `Ctx::project_dir` wants the org's default repository, so on some machines it
would put the *network* there.

**riabuild is still named in full.** The rule in `shims`'s module header is unchanged and
is now load-bearing for every launcher rather than for the clipboard shims alone: riabuild
is the one tool riabuild does not put on `PATH`.

**It is still an `exec`.** `CommandRunner::exec_replacing` is `execvp(2)` — the same system
call the `exec` in the old script made. The developer's shell waits on one process, `Ctrl+C`
reaches the harness, `jobs` shows what they started, and the exit status is the harness's
own. Spawning a child instead would park a riabuild between the terminal and the session
for the whole of its life: two processes where the developer sees one, and a signal
delivered to something that does not know what to do with it.

## Two things that got better rather than merely moving

**`checkout_for` compares path components.** The shell `case` pattern
`"$path"|"$path"/*` was correct only because of where the `/` sat in it: `~/Clubria/payments`
did not swallow `~/Clubria/payments-legacy` by one character's grace. `Path::starts_with`
cannot get that wrong.

**Every path is single-quoted.** The old scripts interpolated paths into `"…"`, where a `$`,
a backtick or a `"` in a home directory would have been expanded or would have ended the
string. Nobody hit it; nobody should have to. `shell::shell_quote` — the workspace's one
POSIX quoter — now wraps every value in every generated file.

## `ngrok` is the same move where it matters most

That shim was the one piece of shell in `bin/` that handled a secret:

```sh
NGROK_AUTHTOKEN=$("…/riabuild" internal ngrok-token)
if [ -n "$NGROK_AUTHTOKEN" ]; then export NGROK_AUTHTOKEN; else unset NGROK_AUTHTOKEN; fi
exec "…/ngrok" "$@"
```

A command substitution whose **stdout was a credential** — which made "print nothing else
on stdout" a rule the whole of `internal ngrok-token` had to keep on the shim's behalf — into
a shell variable, in a process that then went on to `exec`. `riabuild internal ngrok`
fetches the token in the process that *becomes* ngrok and puts it in that process's own
environment. It is in no argument list, on no pipe, in no shell variable, and in no file.

The failure behaviour is unchanged and is still the interesting half: a fetch that fails
prints riabuild's explanation on stderr and starts ngrok with the variable **absent** rather
than empty, because an empty `NGROK_AUTHTOKEN` reads to ngrok as *not authenticated* and
would override a token the developer configured for themselves. `RunOptions::env_remove`
exists because an unset has no spelling in a list of key/value pairs; the Claude launcher's
`unset SSH_CONNECTION SSH_CLIENT SSH_TTY` needs it for the same reason and would be actively
wrong done as `=""`.

`internal ngrok-token` stays. A shim written by an older riabuild is still on disk until the
next provisioning run rewrites it, and that run is not guaranteed to happen before the
developer's next `ngrok`.

## The gates

- `shims::tests::every_generated_script_is_a_single_exec` runs over **every** generator at
  once — so one added later is covered on the day it is written — and fails on a shebang
  that is not first, on more than one line of code, and on `if`, `case`, `for`, `while`,
  `set --`, `$(`, `|`, `&&` or `;` appearing in it.
- `cli::tests::every_generated_launcher_parses_back_into_the_plan_that_wrote_it` closes the
  seam nothing else can see. `riabuild-tasks` writes those files and has no parser;
  `crates/cli` parses them and has no generator — because only the binary may see a clap
  type. A flag renamed on one side compiles perfectly and fails on a laptop the next time
  somebody types `claude`. So the test takes the real generated file, splits its `exec` line
  the way `/bin/sh` would, and feeds the result to the real `Cli` — with a home directory
  that has a space in it, so the quoting is covered too.
- Each harness's `handoff` is unit-tested per branch, including the three the shell version
  could not reach: the interactive agents-view launch, a launch with no terminal, and a
  launch whose recorded binary has gone.
- The `#[ignore]`d smoke tests still run **real** Claude Code, Codex and Grok Build, because
  what they pin is undocumented upstream behaviour and nothing on this side can stand in for
  it. The two that used to run the generated launcher now drive `handoff` and run the harness
  directly: what is under test is the harness, not riabuild's `exec` line, and running the
  launcher would need a built riabuild binary to exec into while asking the same question one
  process further away.

## What this is not a licence to do

The scripts stay. `~/.riabuild/bin` has to hold executables the developer's shell can find
by name, and a one-line `exec` is the cheapest thing that is one. What has moved is the
*deciding*, and the rule is a ceiling: a branch, a substitution or a pipeline reappearing in
a generated file means logic has leaked back out of Rust, and the gate above fails when it
does.

Nor does this apply to the generated **rcfiles**. Those are shell riabuild writes for a
shell to source, on the other side of a handoff riabuild has already made — `bash --rcfile`,
`ZDOTDIR`, `XDG_CONFIG_HOME` — and there is no process there for riabuild to be. The
`tr`/`grep`/`paste` `PATH` strip in `shell::environment` stays for the reason its own comment
gives: one string has to run under both bash and zsh, and zsh does not word-split an
unquoted `$PATH`.
